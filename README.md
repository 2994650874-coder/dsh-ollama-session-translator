# dsh-session-translator

> **本仓库是 [Eyeing0721/dsh-cot-en2cn](https://github.com/Eyeing0721/dsh-cot-en2cn) 的维护分支（fork）。**
> 感谢原作者 Eyeing0721。本分支在其基础上做了以下增强，由本人长期维护迭代：
>
> **为什么它不会给你惹麻烦**
>
> - **零依赖 DSH 内部 API**：全仓库没有一个 `@deepseek-ai/*` 的 import，`dependencies` 是空的。DSH 升级内部结构时，别的插件在 `import failed` 里炸掉，它照常跑。
> - **不碰渲染树**：不占 slot、不替换任何官方组件，只在思考块后面插入自己的 DOM 节点。DSH 改动 UI，最坏情况是它安静地不显示译文，绝不会把聊天界面搞坏。
> - **不碰会话数据**：不写会话日志、不参与轨迹、不碰 KV cache 和上下文压缩。上下文窗口里的内容和你没装这个插件时逐字节一致。
> - **不留残留**：译文缓存在会话自己的文件夹里，卸载插件或删掉会话时一起消失，不存在第三方目录里的孤儿文件。
> - **适配范围**：验证环境为 DSH Desktop 0.2.1-rc.2，但它只用了 3 个稳定 API（`webServer`、`slots`、`locale`），从 rc 时代一路到 0.2.1 都不用改代码。
>
> **功能增强**
>
> - **穿透式折叠翻译**：思考块折叠着也能翻译（从 React fiber 只读原文），「显示原文」与官方思考行联动展开/收回；
> - **追赶式流式翻译**：模型还在思考时译文一段段追赶刷新，结束出全量终稿不跳回；
> - **会话级译文缓存**：译文落在各会话自己的文件夹里，重启不丢、删会话一起删；
> - **自动 / 手动翻译模式**：手动模式点「待翻译」逐段翻；自动模式可调"地平线行数"（视口 ±N 行）；
> - **Ollama 自动发现 + 直连**：「拉取模型列表」自动探测本地 Ollama（`DSH_COT_EN2CN_OLLAMA` > `OLLAMA_HOST` > `127.0.0.1:11434`），点模型即填入，无需注册 provider、无需 key；
> - **空路由显式报错**：翻译模型未设置时明确提示，不再悄悄回落默认模型；
> - **面板暴露「单次输入上限」**、引擎失败原因透出等细节改进；
> - **备用路由 + 静默看门狗**：主路由 504/超时/"连接正常但不再出 token"时自动切备用渠道重试，看门狗只看"多久没新 token"而不是总耗时（总超时会误杀慢但健康的请求）；
> - **备用路由独立分块**：付费渠道无长度限制，可单独设更大的块大小减少请求数；主路由全挂时先发 1 块探针，失败立即整段切备用，不干等 N×30s 网关超时；
> - **内置免费渠道 Index-Translate**：B 站免费翻译 API 作为内置渠道排在服务商列表第一位，无需手填端点、无需 key；
> - **设置面板重做**：自绘下拉（规避 Electron 原生弹层被父级重渲染关闭）、草稿 + 手动保存（含 Ctrl+S）、数字框缓冲提交（规避每按键一次写盘导致的回显覆盖）、按主/备路由分离的额度设置；
> - **环境适配**：已适配 DSH Desktop 0.2.1-rc.2（桌面 webview 同源校验放宽、sessions API 差异适配、思考块 DOM 双保险定位）。
>

## 为什么需要它

在使用 DeepSeek、GLM、Gemini 等推理模型时，模型经常输出大段英文思维链（Chain of Thought）。对于中文母语用户，逐字阅读长篇英文思考过程非常耗费精力。

`dsh-session-translator` 专为解决这个问题设计：
- **不修改任何会话数据**：原文保持原样，只在浏览器界面渲染一层译文面板。
- **不浪费 Token**：折叠的思考块不翻译；原文本来是中文直接跳过；已翻译内容双端缓存。
- **零运行时依赖**：不引入任何第三方 npm 包，仅使用 Node.js 内置模块。
- **不怕 DSH 升级**：不 import 任何 DSH 内部包，不占 slot，不碰渲染树。版本升级时别的插件可能在装载阶段就炸，它只可能安静地少显示一行译文。

## 安装与生效

### 从 GitHub 安装（推荐）

```bash
dsh plugin --profile desktop add https://github.com/2994650874-coder/dsh-session-translator.git
```

国内网络如果卡在下载那一步，先给当前终端设好代理再执行：

```powershell
$env:HTTPS_PROXY = 'http://127.0.0.1:7897'
```

### 从本地目录安装（开发 / 自用）

```bash
dsh plugin --profile desktop add /path/to/dsh-session-translator
```

> 注意：使用本地目录（link 方式）安装时，源目录不可删除或移动，否则插件会失效。

安装完成后，**重启 DSH 桌面端**，刷新浏览器页面即可生效。

### 卸载

```bash
dsh plugin --profile desktop remove dsh-session-translator
```

卸载后，配置文件仍会保存在 storages 目录下，不会丢失。

## 实际行为与使用方式

1. **界面交互**：展开任意「思考」块，中文译文直接渲染在思考原文正下方。译文左侧带有一条竖线，顶部小字清晰展示所用模型、是否命中缓存以及耗时。右上角提供三个操作按钮：`重新翻译`、`复制`、`收起`。
2. **触发机制**：
   - 处于折叠状态的思考块**绝不翻译**，不产生模型调用。
   - 展开思考块时，若模型仍在流式输出，默认等待其思考结束后再翻译，期间显示“模型还在思考，结束后自动翻译…”。
   - 原文为中文时**直接跳过**，不发起请求。
3. **分块与缓存**：长文本会自动按段落、换行或句子边界分块（默认 2000 字符/块）并逐块缓存。二次展开或刷新页面均不会重复调用模型。
4. **主备双路由**：主路由失败（504 / 超时 / 静默卡死）时自动切备用渠道重试一次。静默看门狗的判据是"多久没有新 token"而不是总耗时——总超时会误杀慢但健康的请求。备用路由可单独设更大的分块（付费渠道无长度限制），主路由全挂时先发 1 块探针，失败立即整段切备用。
5. **控制面板**：进入 **设置 → 插件 → 「dsh-session-translator」** 即可打开配置面板。面板顶部是状态与路由信息，紧接着是保存栏，其下是六张设置卡片 + 一个试译框，详见下方「设置项」。

## 设置项

配置文件路径：`$DSH_HOME/storages/session-translator/config.json`（不放在 `settings.yaml` 中，不依赖 schema 库）。手动修改该文件是安全的，所有配置项在载入时都会经过校验并夹紧至合法范围。

### 面板结构

设置页自上而下是：状态区 → 保存栏 → 六张设置卡片：

```text
状态区     当前生效的翻译模型 / 备用路由 / 备用路由执行次数（各带「测试」按钮）
保存栏     所有改动已保存          [放弃改动] [保存]
基础       启用、思考过程中也翻译
翻译模式   自动 / 手动、地平线行数
翻译模型   渠道 / 服务商、模型、拉取模型列表
备用路由   备用渠道 / 服务商、备用模型、备用单次请求上限、静默超时
高级       关闭思考、跳过已是中文、穿透式折叠、目标语言、
           单次请求上限、单次思考的翻译上限、并发请求数、译文文字大小
试译       粘贴一段英文试翻
```

> **保存栏为什么排在第二位**：面板整页较长（实测约 1800px）。保存栏若放在最底部，
> 改完任意一项都得滚过全部卡片才能保存，等于把「怎么保存」藏起来了。
> 现在它紧贴状态区，改完随手就能存。

**面板是"编辑草稿 + 手动保存"模式**：所有改动先落在本地草稿，点「保存」（或按 `Ctrl+S`）才写盘。有未保存改动时顶部与保存栏都会提示，保存按钮从灰色变为可点；保存成功后立即回灰，不闪任何过渡色。点「放弃改动」回到服务端当前值。

试译与两个「测试」按钮都测**当前草稿**，不需要先保存——但草稿只用于该次请求，绝不写盘。

### 字段说明

| 界面上的名字 | 默认值 | 含义 |
|---|---|---|
| 启用 CoT 中文翻译 | 开 | 总开关。关掉后所有译文面板立即消失，原文不受影响。 |
| 思考过程中也翻译 | 关 | 模型还在流式输出时就翻译（会重复调用模型，更费 token）。 |
| 翻译模式 | 自动 | 自动：视口内思考行 ±「地平线行数」自动翻。手动：每块需点「待翻译」。 |
| 地平线行数 | 5 | 自动模式下，翻译视口内思考行上下各 N 行。 |
| 渠道 / 服务商 | 空 | 翻译请求走哪个渠道。列表来自 DSH 已注册渠道 + **内置的 Index-Translate（B站免费）**。也可切「自定义端点」手填 `http(s)://` 地址直连 OpenAI 兼容服务。**留空 = 不翻译**，不会自动用付费默认模型。 |
| 模型 | 空 | 所选渠道下的模型。渠道切换时自动清空，避免把 A 渠道的模型名填到 B 渠道上。 |
| 备用渠道 / 服务商 | 空 | 主路由失败时重试用的渠道。留空 = 不启用备用路由。 |
| 备用模型 | 空 | 同上。 |
| 备用单次请求上限 | 0 | 备用路由自己的分块大小。付费渠道无长度限制，拉大可减少请求次数（少付重复的系统提示词）。**0 = 跟随主路由**。 |
| 静默超时 | 5000 毫秒 | 连续这么久没有新 token 就判定卡死并切备用路由。判据是"多久没新 token"而不是总耗时——实测健康流式的 token 间隔中位数 26ms、最大 315ms，5000ms 有 14 倍余量。0 = 关闭看门狗。 |
| 关闭思考（推荐） | 开 | 请求里带 `reasoningEffort: "off"`，让翻译不产生思考 token。**不是所有渠道都支持**：不支持时自动降级重试并记住，不会因此翻不了译。实测关掉后 3800 字从 27.2 秒降到 3.1 秒。 |
| 跳过已是中文的思考 | 开 | 原文本来就是中文时直接跳过，不调用模型。阈值：英文 ≤16 字母，或汉字 ≥ 英文×6。含英文句子的混杂内容一律照翻。 |
| 穿透式折叠翻译 | 关 | 折叠状态下也翻译（从 React fiber 只读原文）。 |
| 目标语言 | 简体中文 | 还可选 繁體中文 / English / 日本語。 |
| 单次请求上限 | 2000 | **每次请求**发给服务商的字符上限。默认免费服务商存在限额（B站翻译模型为 3000 字符），如已更换渠道可拉高。调小更稳（不容易被 max-tokens 截断），但请求数变多。 |
| 单次思考的翻译上限 | 50000 | 翻译**一个思考块**时的总字符闸（范围 500~200000）。超出时从末尾向前找第一个完整自然段处截断，截断处往后丢弃，并提示「原文过长，仅翻译了前一部分」。 |
| 并发请求数 | 2 | 同时发往服务商的请求数上限。免费端点建议 2：实测 2 路 × 2000 字是安全值，4 路会挂。 |
| 译文文字大小 | 13px | 只影响译文面板。 |

> **两个上限的区别**：`单次思考的翻译上限` 决定"整段思考最多翻多少字，超出部分丢弃"；`单次请求上限` 决定"切多大块发一次请求"。两者独立，后者乘以前者没有意义。

> `timeoutMs`（单次总超时）与 `cacheEntries`（服务端缓存条数）仍在配置文件里、引擎仍在用，但**不再暴露到面板**：总超时会误杀慢但健康的请求（判据已由静默看门狗接管）；译文已直接注入会话文件夹，服务端 LRU 退化成同会话内的去重缓存。

## 原理与安全性保证

插件采用双端架构：
- **宿主端（lib/index.js）**：注册八条本地同源路由：
  - `GET /dsh-session-translator/state` —— 当前配置 + 运行计数 + 生效路由
  - `PUT /dsh-session-translator/config` —— 整份配置写盘（面板保存的唯一入口）
  - `POST /dsh-session-translator/translate` —— 翻译一段文本（可带一次性草稿覆盖）
  - `GET /dsh-session-translator/providers` —— DSH 已注册渠道
  - `GET /dsh-session-translator/models` —— 渠道下的模型
  - `GET /dsh-session-translator/catalog` —— 渠道 + 模型两层清单（内置渠道排第一）
  - `POST /dsh-session-translator/test` —— 主路由 / 备用路由连通性自检
  - `POST /dsh-session-translator/cache/clear` —— 清空服务端缓存
  翻译请求默认通过 DSH 的 `ctx.llm.stream()` 发起，复用用户在 DSH 中既有的模型渠道与凭据；Provider 为 `http(s)://` 端点时直连该 Ollama 的 OpenAI 兼容接口（`/v1/chat/completions`），本地模型零配置可用。翻译接口与配置接口严格限制仅接收本机（`127.0.0.1`）且同源的请求。
- **浏览器端（lib/client.js）**：利用 `MutationObserver` 监听对话视图，寻找带有 `data-variant="think"` 属性的思考节点（带类名兜底），在思考正文下方动态插入独立的译文 DOM。

为什么不做成官方插槽：DSH 的 slot 系统未提供针对“单块思考”的细粒度位置，若替换 `conversation.chat.node` 会强行覆写整个 assistant 渲染器，改动过重，因此采用只做 DOM 增强的实现方式。

由此提供四项确定性保证：

1. **绝不污染会话数据**：插件不写会话日志，会话记录、轨迹（Trajectory）视图、KV cache、上下文压缩完全不受影响。上下文窗口里的内容和你没装这个插件时逐字节一致。
2. **零副作用**：随时停用插件，界面恢复原生状态，不留痕迹。
3. **优雅降级**：若未来 DSH 调整了思考块的 DOM 结构，插件仅安静地不显示译文，绝不会破坏宿主页面的正常渲染。
4. **不怕版本升级**：它只用了三个 DSH API——`webServer`（注册路由）、`slots`（设置页一张卡片）、`locale`（中英文案）。三者都是稳定面，且每次调用前都做 `typeof === 'function'` 检查，服务不在就静默跳过对应功能。它既不静态 import DSH 内部包，也不读写 DSH 的会话日志格式，所以 v3 → v4 这类格式迁移与它无关。

### 为什么译文缓存不会污染会话

这是最容易被怀疑的地方，所以说明白：译文缓存在会话目录下的文件名是 `session-translator-translations.json`。

DSH 自己的会话日志文件名叫 `session.v4.jsonl.zstd`（无压缩时 `session.v4.jsonl`）。它查找会话日志时用严格的文件名匹配——剥掉压缩后缀后必须形如 `session` 或 `session.vN`，而且必须以 `.jsonl` 结尾。`session-translator-translations.json` 三条都不满足，DSH 会直接跳过这个文件。

而且 DSH 读取一个会话时，只打开通过上述筛选得到的**唯一一个**日志文件，不会遍历目录里的其他文件。所以那 700KB 的译文缓存对你和模型都是不可见的——它只是插件自己的便签本。

会话被删除时，译文缓存随文件夹一起消失，不存在残留。

| 配置项默认值 / 取值范围 | `config.js` 的 `DEFAULT_CONFIG` 与 `NUMBER_BOUNDS` |

### `lib/client.js` 的四段结构

这个文件最大，按注释里的分隔线切成四段：

| 段 | 起始行 | 内容 |
|---|---|---|
| utilities | L~274 | 会话 key、hash、HTTP 封装、客户端缓存 |
| inline translator | L~320 | 译文面板：DOM 监听、定位思考块、注入面板、选区保护、live 流式 |
| settings UI | L~1030 | 设置面板：`createSection()`、`Dropdown`、`NumberInput`、六张卡片 |
| wiring | L~2136 | `apply(ctx)`：注册 locale、绑定 sessions、挂载 slot |

### 关键不变量（改代码前必读）

1. **原文永不修改**。插件只在 DOM 里插节点，不碰会话数据、轨迹、KV cache。
2. **面板是草稿 + 手动保存**。`edit()` 只改本地草稿，写盘只有 `saveAll()` 一处。
3. **`group()` 的 children 可能含数组**（`.map()` 返回值），补 key 前必须压平，否则 React 渲染对象会崩掉整页。
4. **关思考用 `reasoningEffort: 'off'`**，不是 `purpose`。DSH 的 `purpose` 只影响 `compaction` 的 header。
5. **两个上限语义不同**：`maxInputChars` 决定"整段最多翻多少字"（超出丢弃），`maxChunkChars` 决定"每次请求切多大"。

## 隐私与调用开销

- **不触碰 API Key**：插件不包含、不索取、不存储任何 API Key，所有调用完全基于宿主已配置的通道。
- **按需消耗**：折叠不翻、中文跳过、切块复用。并发请求控制在阈值内（默认 2），单次超时受控（默认 120 秒）。
- **完全本地**：无外部数据上报，所有逻辑均在本地 Node.js 进程与浏览器之间完成。

## 常见问题 (FAQ)

**Q: 展开思考块后没有出现译文？**
A: 请按顺序排查：
1. 设置面板中的「启用 CoT 中文翻译」总开关是否处于开启状态；
2. 该思考块是否仍处于流式生成中（默认策略会等待思考完成后自动触发）；
3. 思考原文是否本来就是中文（插件会自动跳过中文内容）；
4. 查看译文位置是否有报错提示信息，如网络超时等。

**Q: 译文面板提示“翻译模型未设置”？**
A: 插件设置里的 Provider 与 模型 有一项或两项留空。两者必须同时填写；插件不会自动改用付费默认模型。本地有 Ollama 的话，点「拉取模型列表」即可自动发现并一键填入。

**Q: 提示输出被 max-tokens 截断？**
A: 思考文本较长时，可以在设置中将「单块字符数」调小（例如调整为 1500）。

**Q: 译文会记录在轨迹（Trajectory）视图里吗？**
A: 不会。插件仅在 Web 对话视图的思考块后插入临时渲染节点，不进入轨迹记录。

**Q: 写在会话文件夹里的翻译缓存，会不会被当成上下文喂给模型？**
A: 不会。缓存文件名是 `session-translator-translations.json`，而 DSH 只认 `session.v4.jsonl.zstd` 这类名字——必须形如 `session` 或 `session.vN` 且以 `.jsonl` 结尾，我们的文件名三条都不符合，DSH 查找会话日志时会直接跳过。它读一个会话也只打开唯一一个日志文件，不会遍历目录。详见上面的「为什么译文缓存不会污染会话」。

**Q: DSH 升级后这个插件会不会挂？**
A: 它不 import 任何 DSH 内部包、不占 slot、不碰渲染树，只用了 `webServer` / `slots` / `locale` 三个稳定 API，且每次调用前都做存在性检查。升级后最坏情况是思考块的 DOM 结构变了导致译文不显示——换个角度说，这时它会安静地什么都不做，而不会把界面搞坏。

**Q: 会与其它 Web 插件冲突吗？**
A: 不会。插件不占用任何 slot 插槽，不替换既有渲染器。译文面板内按钮的点击事件均在捕获阶段拦截，不会误触发宿主思考块的展开或折叠。

**Q: 卸载/升级命令里的名字到底该写哪个？**
A: **`dsh-session-translator` —— 只有这一个名字。**

2026-10-19 起技术包名与显示名已统一：`package.json` 的 `name`、cordis 插件 id、
`/dsh-session-translator/*` 路由前缀、`storages/session-translator` 配置目录
全部是同一个值，不再有「显示名 / 技术名」两套体系。

```bash
dsh plugin --profile desktop add    https://github.com/2994650874-coder/dsh-session-translator.git
dsh plugin --profile desktop remove dsh-session-translator
```

## 更新日志（本地增强分支）

> 本仓库是 [Eyeing0721/dsh-cot-en2cn](https://github.com/Eyeing0721/dsh-cot-en2cn) 的维护分支（fork），以下为分支上的增强。

### 2026-10-19

**设置面板重做**

- **自绘下拉**（`custom-dropdown`）：原生 `<select>` 在 Electron 里由系统绘制弹层，父级任何一次重渲染都会把它关掉（"一拉就弹回去"）；且 DSH 全局 CSS 给 `select` 配了背景箭头，宽控件上会平铺成"一整片蓝色箭头"。改成按钮 + 内联展开列表，两个问题一起消失。
- **草稿 + 手动保存**（`manual-save`）：原来每次交互都直接 `PUT /config`，改错了没法撤销、多个改动之间面板会闪、5 秒轮询与写请求互相覆盖。现在所有改动落在本地草稿，点「保存」或按 `Ctrl+S` 才写盘；「放弃改动」回到服务端值。
- **数字框缓冲提交**（`number-buffer`）：原来每敲一个数字发一次写请求，打 `8000` 会发 `8/80/800/8000` 四次，中间态被钳到下限、响应乱序时后到的旧值会盖掉新值（"填了不保存、回弹 0"）。现在失焦或回车才提交一次。
- **保存按钮两档配色**（`save-button-tone`）：只在"灰（无可保存）↔ 普通（有改动）"之间切换，保存成功后直接回灰，不闪过渡色。保存中保持白色只置禁用，避免"白→灰→灰"的突兀闪回。
- **独立保存栏**（`save-bar`）：与上方卡片同宽、单行高。**位置在状态区正下方、第一张卡片之前**（原在最底部，因"保存按钮很难发现"移到顶部附近）。
- **状态卡片精简**（`status-slim`）：只留"现在用的什么、能不能用"三行，每行带一个「测试」按钮；删掉译文缓存行与配置文件路径行。

**路由与额度**

- **备用路由**（`fallback-route`）：主路由失败时用备用渠道重试一次，备用路由的缓存键单独计算。
- **静默看门狗**（`fallback-route`）：判据是"多久没新 token"而不是总耗时。总超时会误杀慢但健康的请求（实测有 27s、36s 的正常响应）。
- **备用路由独立分块**（`fallback-chunk`）：付费渠道可单独设更大的块大小；主路由全挂时先发 1 块探针，失败立即整段切备用，不干等 N×30s 网关超时。实测 3 万字：主路由 1 次探针失败 → 备用 4 次成功，对比"备用也用 2000 字"需要 15 次。
- **按路由分离的额度**：`单次请求上限`（主路由）与 `备用单次请求上限`（备用路由）独立配置。

**内置渠道**

- **Index-Translate（B站免费）**（`builtin-index-translate`）：不是 DSH 注册渠道，但作为内置渠道排在 `/catalog` 第一位，无需手填端点、无需 key。内置三个模型：`Index-Translate-35B-A3B`（旗舰）、`index-mt-9b`（均衡）、`index-mt-2b`（最快）。**实测限制**：非流式 >3000 字必 504，并发 2 路 × 2000 字是安全值。

**引擎修正**

- **关思考机制纠正**（`thinking-off`）：旧实现设 `purpose: 'session-title'` 并指望适配器映射成关思考——**这是错的**，`dsh-llm-deepseek` 的 `serialize()` 只读 `reasoningEffort`，全文件里 `purpose` 只影响 `compaction` 的 header。所以这个开关从装上起就没生效过。改用 `reasoningEffort: 'off'`（官方 translator 的做法），并对不支持该参数的渠道自动降级重试。
- **自然边界截断**（`clip-boundary`）：原来 `slice(0, max)` 从句子中间硬砍，半个句子交给模型只会得到半个译文。现在段落 → 行 → 句子三级回退。
- **endpoint 模式 SSE 流式**（`endpoint-stream`）：旧实现发 `stream: false`，整段译文一次性到达，看门狗会把任何超过 N 秒的健康请求误判成卡死。

**沿用上游修复**

本分支已合入上游 2026-10-06 的三个修复，并在其基础上继续开发：
- `select-safe`：幂等写入 + 选区保护（拖选译文时延迟补写，不再"选中间一段把前面一并带入选区"）
- `retry-force`：`force` 穿透分块 LRU 缓存（"重新翻译"不再秒回一字不差的旧稿）
- `skip-policy`：收紧"已含中文跳过"阈值（`latin<=16 || cjk>=latin*6`），中英混杂内容一律照翻

### 2026-10-06

- **译文可局部选中复制**（`select-safe`）：修复译文"选区跳到开头、松开即消失"——渲染幂等化（同值不写）、缓存命中补记 `srcKey`（斩断 220ms 自持注重写循环）、用户选区落在面板内时延迟补写。
- **「重新翻译」真重翻**（`retry-force`）：修复长文本重翻"闪一下没动静"——`force` 穿透分块 LRU 缓存。
- **中英混杂照翻**（`skip-policy`）：收紧"已含中文跳过"阈值，思考开头的混杂内容不再被原文当译文放出；跳过时面板明示「原文已含中文 · 未翻译」。
